# Проверка качества и релизов RIVER

Качество оценивается по итоговому результату пользователя. Найти похожий документ недостаточно, если нужный факт не дошёл до генерации. Убедительный ответ с неверной ссылкой, числом или скачиваемым файлом тоже считается ошибкой.

## Проверка изменения

1. Зафиксировать вопрос, ожидаемые источники, вложения и нужный контекст чата; воспроизвести ошибку.
2. Сохранить, какие факты дошли до финального контекста и что увидел пользователь.
3. По возможности менять один механизм за раз; повторить тот же случай и соседние случаи на регрессии. Неудачные подходы сохранять в инженерных отчётах.
4. Проверить содержимое DOCX/XLSX и браузерный сценарий. Успех unit-тестов или факт скачивания файла сами по себе недостаточны.

Так были исключены некоторые возможности: CPU cross-encoder reranker на измеренных случаях замедлял запрос и ухудшал расположение важных юридических фактов. Расширение обзорных каналов для каждого вопроса вытесняло точные источники, поэтому они ограничены обзорными задачами.

## Действующие проверки

| Уровень | Что проверяется |
|---|---|
| Детерминированные регрессии | Нормы, доступ, биллинг, формы и инварианты документов; часть набора выполняется без LLM. |
| Повтор пользовательских случаев | Ранее встреченные вопросы и вложения с сохранением ответа и файлов для содержательной проверки. |
| Browser E2E | Playwright проверяет вход, чат, формы, скачивание и просмотр документов. Это отдельная проверка, не обещание ночного запуска каждого браузерного сценария. |
| Ночная задача | Здоровье сервиса, регрессии, lint недавних документов, пассивные сигналы качества, ограниченный LLM judge и состояние семантического кэша шаблонов. |
| Релиз | Скрипт компилирует код, перезапускает сервис, проверяет здоровье и запускает регрессии. Затронутый пользовательский сценарий и метрики сервера проверяются отдельно. |

LLM judge помогает определить, какие ответы стоит проверить вручную. Он не является эталоном юридической точности. Публичной сквозной оценки качества здесь нет: рабочий корпус и пользовательские случаи закрыты. Числа документов и чанков в README измеряют только размер индекса.
